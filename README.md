# DogTray

Windows 托盘启动器，纯 Rust + Windows 自身 API，没有第三方 crate 依赖。

- 启动时读当前目录下的 `start_config.ini`；找不到就弹对话框
  “缺少配置文件 start_config.ini”，点确定后退出。
- 配置按 `[XXXX]` 分段，每段正文就是一段 Windows cmd 批处理，
  按段顺序启动，每段启动后等 5 秒再启动下一段，不弹黑窗口。
  启动时先显示一个进度窗口，列出所有 `[XXX]`：正在启动的那段是
  蓝色转圈“启动中…”，已经启动完的是绿色“√ 已启动”，还没轮到的是
  灰色“○ 待启动”，启动失败的是红色“× 启动失败”，标题还会显示
  “已完成 x/y”。全部段都启动完（包括最后一段的 5 秒间隔走完），
  进度窗口自动消失，只留托盘图标。进度窗口点 X 可以提前关掉它，
  不影响正在启动的程序。段多时窗口会自动分多列（最多四列），
  高、宽都封顶在屏幕的 80%，再多就压缩行距，最后一行不会被截掉；
  列数分两步算：先算宽度能容纳的最大列数，再在这个范围内找
  高度能放下的最小列数，都放不下时用宽度允许的最大列数再压缩行距，
  不会因为 4 列太宽而让窗口右边伸出屏幕外。窗口尺寸由客户区经
  AdjustWindowRectEx 反算，高 DPI / 换主题也不会算错。
  窗口不置顶、不抢焦点，被启动的程序弹出登录框、确认框时不会被它盖住。
  进度窗口用 Microsoft YaHei UI 字体，转圈用 ASCII 的 | / - \，
  已启动用 √，不会因字形缺失显示成方框；转圈符号单独放在
  固定宽度 20 像素的小标签里，YaHei 是比例字体，| / - \ 宽度不同
  也不会让段名左右抖；文字用窗口背景色不透明绘制，不会叠出残影；
  定时器只刷新正在启动的那一行和状态变了的行，不会整屏闪烁。
  行距压缩时字号一起调小（30 行距 16 像素、24 行距 14 像素、
  20 行距 13 像素），标签高度等于行距，不会把汉字下半截裁掉。
  注意：“已启动”只表示 cmd 拉起来了，不表示脚本里的程序真的跑起来了：
  如果脚本里程序路径写错了、程序一启动就闪退，仍会显示绿色“已启动”，
  这是方案本身的限制，要看输出窗口或日志才能发现。
- 单实例：标识只用配置文件全路径，不用 exe 路径。判重的本意是
  “防止重复启动同一批程序”，而要启动哪批程序由 start_config.ini
  决定，不是由哪个 exe 决定的：同一份配置无论用哪个 exe 启动
  都会被拦；同一份 exe 从两个工作目录启动，读的是两份不同的配置、
  要启动两组不同的程序，不算重复。配置文件路径先用 CreateFileW
  加 FILE_FLAG_BACKUP_SEMANTICS 打开它所在的目录，再用
  GetFinalPathNameByHandleW 拿目录的最终路径、拼上文件名，
  所以同一个目录通过映射盘符和 UNC 两种方式访问，也会得到
  同一条路径；取不到最终路径时退回 GetFullPathNameW 的语法规范化。
  标识是规范化后的配置路径转小写后做 FNV-1a 哈希，只把哈希放进
  互斥名，所以全路径里的中文、空格、长路径都不会出问题。
  已经有一个实例在跑时，再双击会弹“程序已经启动，请不要重复运行”，
  点确定后退出，不会再启动第二个。
- `[main]` 里配主程序和其它选项，例如：

```ini
[xray]
cd frpSchool-win
run.bat

[chrome]
set CurrentDir=%~dp0
"App\Chrome.exe" --start-maximized --proxy-server="127.0.0.1:11083"

[main]
main=chrome
output_log=false
title="海大穿梭"
```

- `main=chrome`：chrome 段是主程序。主程序及其全部子进程都退出后，
  DogTray 关掉其它段再退出；DogTray 自己退出时也关掉全部子程序。
- `output_log=true`：在当前目录生成和程序同名的 `.log`
  （如 `DogTray.log`），记时间、哪个程序启动、哪个程序退出。
- `title="..."`：托盘悬停文字；没配就用 exe 文件名（不带 `.exe`）。
- `anchor_dirs=...`（可选，只在需要时配）：手工追加锚点目录，分号分隔，
  可以写在 `[main]`（作用于所有段）或某个 `[XXX]` 段里（只作用于该段），
  该段里的这行是配置行，不会放进批处理脚本执行。
  用途：启动器活得较久、被观察到了，然后再拉起另一个目录里的真正程序
  并退出时，自动锚点只记了启动器的目录，真正的程序会被判成外来、
  段被提前判定退出。遇到这种程序（python run.py、node app.js、
  java -jar xx.jar，或者“启动器 + 主程序”分装在两个目录）时，在对应段里
  写上真正程序的目录，例如：

```ini
[myapp]
anchor_dirs=D:\Tools\MyApp;E:\MyApp\bin
python run.py
```

  平时不用配，自动锚点已经够用。路径先展开环境变量（`%LOCALAPPDATA%` 等），
  再用 GetFullPathNameW 规范化相对路径、`.` 和 `..`、盘符相对写法，
  最后转小写、补末尾反斜杠，所以 `..\tools`、`%LOCALAPPDATA%\VirtualBrowser`
  都能匹配上规范化后的 exe 路径。手工锚点单独存，不混进自动锚点：
  判断核心时同时查自动和手工两个集合，但“自动锚点是否为空”的兜底
  （核心兜底、孤儿锚点启用、路径兜底）只看自动的，所以配了手工锚点
  也不会让自动机制的兜底失效。注意：不要把盘符根（`D:\`）写成手工锚点，
  那会把整个盘都算成核心；手工目录是用户显式配的，程序不会像自动锚点
  那样把它降级，写错了就真的按整个盘算。
- 托盘左键打开主界面：每个 `[XXX]` 一个按钮（`[main]` 不算）。
  点按钮打开该程序的输出窗口，显示它的 stdout + stderr。
  每段输出在内存里只留最近 2MB，超了删前面、新信息追加到后面。
  输出窗口每 200ms 刷新：滚动条到底才跟随滚动，手动滚离则不跟随；
  关闭输出窗口不杀程序，再点主界面按钮可重新打开。
- 退出时统一优雅关闭：先给有窗口的程序发 `WM_CLOSE` 等 5 秒（无窗口的程序一同等，因为它可能依赖窗口程序）；然后重新枚举所有还没退出的程序，给它们发关机通知（`WM_QUERYENDSESSION` + `WM_ENDSESSION`）再等 5 秒；还不退的才全部强行终止。托盘菜单返回后若关机已跑过，外层会补发退出消息，避免菜单内部循环吞掉退出消息导致 DogTray 本身不退。子进程按 PID + 创建时间跟踪，防止 PID 复用后误判活着或杀错进程。主段根进程已退、后代还活着时，每 30 秒写一条诊断日志（进程 PID + 进程名），只在这种反常情况下写，且受 output_log 控制：output_log=false 时不写，output_log=true 时才写。
  子程序用作业对象（Job Object）+ 进程快照双重跟踪，短命的中间
  launcher 退了、真正的浏览器还在时也不会误判为整段已退出。
  快照父子链加入时必须通过创建时间顺序检查：子进程创建时间晚于父进程，
  且父进程已死时子进程创建时间不能晚于父进程最后一次活着 + 5 秒，
  否则不加入，防止死父进程 PID 被复用后把 v2rayN 之类的无关进程树误吸进来。
  退出判定和强杀都以作业对象为准，再以锚点目录区分核心/外来：
  作业分配成功时，根进程已退且作业里没有核心进程就算整段退出。
  锚点是根 cmd 直接子进程的 exe 归属：非 Windows 目录记目录，
  Windows 目录只记完整路径。路径落在锚点目录、或等于锚点完整路径的
  才是核心进程；其余外来进程（搜狗 SGTool、360 注入模块等，即使进了作业）
  不阻塞退出，也不会被发关闭消息或强杀。诊断日志只报核心阻塞，
  外来进程单独列为已忽略。只有作业分配失败时才回退到快照判断。
  细节：创建时间比较用原始 FILETIME（100 纳秒），不转秒，否则同一秒内
  创建的 cmd 和子进程会被误判为复用而记不上锚点；直接子进程还必须早于
  根 cmd 退出时间（GetProcessTimes 拿退出时间），防止根 cmd 退出后 PID
  被复用；兜底只看 anchor_dirs 是否为空，Windows 目录完整路径锚点
  （xcopy、timeout）不算主程序；父进程已死、且从未被观察到的作业成员
  也记锚点，覆盖启动器早死、第一次轮询前就退出的情况，但孤儿锚点
  只在直接子进程记完后 anchor_dirs 仍为空时才生效，一旦主程序目录
  已记上，之后不再接受孤儿锚点，防止外来软件经短命中间进程中转
  拉起常驻进程时把自己的目录记进来，孤儿阶段二一轮只记一个目录锚点，
  记上就立即停；exe 路径按 PID + 创建时间全局缓存，Windows 目录只取
  一次，已记锚点的直接子进程不再重复查路径；创建时间不缓存，每次现查，
  避免 PID 在缓存有效期内被复用时误判为旧进程（这也影响 remaining_pids
  作业无效回退分支的 WM_CLOSE / 关机通知对象）；根 cmd 退出时间先用
  WaitForSingleObject 确认已退出再取，未退出时返回 0，且每段每轮只取一次。
  自动锚点如果落在盘符根（`D:\`）、用户目录根（`%USERPROFILE%\`）、
  UNC 共享根（`\\server\share\`）会过宽，整个盘、整个用户目录里的输入法
  都会变核心，所以自动记录时降级为只记完整路径，不记目录。
  强杀时不再按 PID 重开进程：判定核心时就用
  `PROCESS_TERMINATE | PROCESS_QUERY_LIMITED_INFORMATION` 拿到句柄并持有，
  强杀直接用这个句柄，持有句柄期间 PID 不可能被复用；句柄拿到后还会
  复核创建时间，复用发生在快照和打开之间时再按句柄进程的 exe 路径重判，
  外来复用进程不杀、核心复用进程照杀；句柄打不开时才退回按 PID 打开、
  创建时间校验的老路，杀完关句柄。`remaining_pids` 直接返回
  (PID, 所属段下标, 判定当时记录的创建时间)，句柄复核和强杀回退都用
  这一份数据，不再按 PID 反查别的段的旧条目，避免 A 段很早以前用过的
  PID 被 B 段核心进程复用时，用 A 段的旧时间和旧锚点把该杀的判成外来而漏杀。
- 运行期间每段会生成一个 `__dogtray_*.bat` 临时文件（为了让脚本里的
  `%~dp0`、相对路径按原意工作），每段启动后 5 秒就删掉，不等到退出。

## 目录结构

```
Cargo.toml          包配置（无第三方依赖）
Cargo.lock
build.rs            编译时把 dog.ico 嵌进 exe（windres / rc.exe）
resource.rc         图标资源：1 ICON "dog.ico"
dog.ico             卡通狗头图标（256/48/32/16）
generate_icon.py    重新生成 dog.ico 的脚本（需要 Pillow）
src/main.rs         全部程序逻辑（托盘、启动、跟踪、关闭、输出窗口）
.cargo/config.toml  Linux 交叉编译时用的 mingw 链接器配置
```

## 编译（推荐：Linux 交叉编译，和作者原来一样）

```bash
rustup target add x86_64-pc-windows-gnu
# Ubuntu/Debian：
sudo apt install gcc-mingw-w64-x86-64
cargo build --release --target x86_64-pc-windows-gnu
# 产物：target/x86_64-pc-windows-gnu/release/dog-tray.exe
# 改名成 DogTray.exe，和 start_config.ini 放同一个文件夹里运行。
```

`.cargo/config.toml` 里已经配好了
`linker = "x86_64-w64-mingw32-gcc"`，不用再手动传链接器。

## 编译（Windows 本地）

先装 Rust（https://rustup.rs/），然后二选一：

1. MSVC（推荐在“开发者命令提示符”里，rc.exe 才在 PATH 里）：

```bat
cargo build --release
```

2. MinGW（MSYS2 的 mingw64 环境）：

```bat
rustup target add x86_64-pc-windows-gnu
cargo build --release --target x86_64-pc-windows-gnu
```

如果找不到 `windres` / `rc.exe`，编译不会中断，只是 exe 图标会
回退为系统默认图标，程序功能不受影响。

## 运行

把 exe 和 `start_config.ini` 放同一个文件夹，双击 exe 即可。
注意：例子文件如果叫 `start_config-2.ini`，要改名成 `start_config.ini`
程序才会读到。右下角托盘图标是卡通狗头；左键打开主界面，
右键菜单“退出程序”退出；主界面点 X 只隐藏回托盘，不退出。
