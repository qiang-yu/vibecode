---- 数据处理逻辑 ----

---- 没有 tool 注入的数据 ---

1. 原始数据文件，Hermes 格式的 ShareGPT 文件
    glaive-function-calling-5k.json

2. 去除自带的 System 内容 (让 tools 列表自动生成)
    func-calling-remove-system.py
    glaive-function-calling-5k-no-system.json

3. 插入更多的 tools 
    原始文件，每个 ShareGPT 内容的  "tools":[...] 里面只带了需要用的1-2个 tool，没有更多了
    模型微调的时候会导致模型如果发现有更多的 tool 用不上，就不会推理 <tool_call_security>
    可能是过拟合了，所以我干脆随机插入更多用不上的 tools ，这样就不会有问题了
    inject_tools_only.py

4. 重新推理生成 from:gpt 的内容，要带 <think>标签
    infer-func-calling-data-with-think-32b.py
    glaive-function-calling-5k-inference-32b.json

5. 去除推理错误的内容，推理的 tool_call 和之前的 tool_response 函数对应不上，推理错了
    check-inference-tool_call-consistent-clean.py
    glaive-function-calling-5k-inference-32b-clean.json
    
6. 生成 <tool_call_security> 标签
    qwen_reanson_tool_call_security.py
    glaive-function-calling-5k-inference-32b-clean-tool-call-security.json
    
    这里就可以去微调 Qwen 模型了 
    
---- 注入了 tool 的数据 ---    

1. 在 tool_response 中，随机注入另外一个 tool
    inject_tool_call.py
    原始：glaive-function-calling-5k-no-system.json  (随机挑选另外一个 tool 注入到当前一个 ShareGPT 数据中)
    结果：glaive-function-calling-5k-injected.json
    
2. 注入的文件 重新推理生成 from:gpt 的内容，要带 <think>标签
    infer-func-calling-data-with-think-32b.py
    glaive-function-calling-5k-injected-inference-32b.json 

3. 清理注入无效数据    
    在 tool_response 中注入另外一个 tool，可能推理的时候没推理出来这个注入的 tool_call，清理掉注入无效的数据
    clean-inject-item-with-no-reason-tool_call.py
        
4. 生成 <tool_call_security> 标签
    qwen_reanson_tool_call_security.py
