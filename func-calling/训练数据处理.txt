
1. 用 infer-func-calling-data-with-think.py 对原始数据，跑一遍 Qwen3-8B 多轮对话的推理，用生成的内容替换之前的数据中内容
    因为我需要大模型自己生成的数据，包括 <think>...</think> 思维链
    
    对于 injected 的数据，程序配置了 2个模型， small_model="qwen3-8b"  big_model="qwen3-32b"
    injected 的数据，普通推理用 small_model，对于 inject 的内容的“下一条”用 big_model 推理，其它依然用 small_model 推理
    
    /home/qiangyu/ClaudeCode/deal-func-calling-file/func-calling/Qwen3-8B/glaive-function-calling-5k-think-8b.json
    
    
2.  推理之后数据，可能发生推理的 tool_call 中的 func_name 和下一条 tool_response  中的 func_name 不一致的情况，需要清理
    check-inference-tool_call-consistent-clean.py
    
    
3. 对于 inject 的数据，可能会发生 “inject”  的内容理论上会让大模型生成被劫持的 tool_call，但是，也有可能根本没生成 劫持的 tool_call
    对于没有生成劫持的 tool_call，数据需要 clean ，把没有劫持tool_call但是始终却有对应 tool_response 的数据清理掉
    clean-inject-item-with-no-reason-tool_call.py 
    
    
4. 对于清理的数据，用 Qwen3-32B 生成 <tool_call_security>...</tool_call_security>，放到 </tool_call>的后面
    reason_tool_call_security.py
    
5. 随机给数据加入更多 tools
    inject_tools_only.py 
    原始的训练数据，都是用到哪些 tools 就只包含这些 tools，这会让模型学会“用所有这些 tools”
    随机给训练数据加入更多 “不用 凑数”的 tools，这样模型需要学会“挑选正确的 tools”    
       
6. 检查 tool_call 后面必须一定跟一个 tool_call_security，如果没有，就丢弃这个数据
    check_tool_security_after_tool_call.py      会生成 clean 的数据文件
        
7. 检查 tool_call_security 判断是否正确    
    (1) 非 inject 的内容， tool_call_security 必须是  safe
    (2) 是 inject 的内容， tool_call_security 不能是  safe
    clean-tool_call_security-safe-unsafe.py
        
8. 训练数据大部分都在 8192 个 token 以内，只有很少数才会超过 8192，我们把超过 8192 的数据删除，这样训练的时候只需要 cut_len 8192 就可以了，可以大幅让训练速度大幅提升
    check_seq_len.py
    cut_seq_len.py
